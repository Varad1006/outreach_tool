Outreach Agent architecture

A local, single-user web app. It finds clients that match your profile, scrapes their websites into AI-ready leads, writes personalised emails with Claude, sends them from your own mailbox and tracks replies.

How a lead moves through the system

The numbers match the circles in the diagram.

1Import

Your lead sheet (.xlsx or Google Sheets link) is read into the database. Re-imports update details but keep your statuses and history.

2Find & scrape

Claude turns your profile and past-lead results into target segments, then finds matching businesses. The scraper reads each site and scores how much it needs AI.

3Write

Claude writes the evidence, pitch, opener and a 3-email sequence for each lead. You can rewrite any email with one click and your own instructions.

4Send

Approved emails go into a queue. The worker sends them one by one from your Hostinger mailbox, with random gaps and a daily cap. Follow-ups are sent in the same thread.

5Track

"Check replies" reads your inbox over IMAP. Replies, bounces and opt-outs update the lead's status and stop any further follow-ups.

6Export

Statuses and notes are written back into your original workbook, so the spreadsheet stays your source of truth.

Why we used what

Python + Flask web app

One small language for everything: scraping, Excel, email and the Claude SDK all have mature Python libraries. Flask serves the pages with almost no setup.

Instead of: Node/Next.js (two languages, a build step); Django (more structure than a one-person tool needs).

Server-rendered pages (Jinja) UI

Pages are built on the server with plain CSS and a little JavaScript. No build tools, nothing to compile, and they load instantly. Dark mode and phone layout are built in.

Instead of: React SPA (needs an API layer and a bundler, with no real gain for a single user).

SQLite database

One file (data/outreach.db), zero setup, easy to back up by copying it. Thousands of leads and emails are a tiny load for SQLite.

Instead of: Postgres/MySQL (a server to run for no benefit at this size). Switch if several people need to use it at once.

Background threads workers

Three lightweight threads handle scraping, bulk AI drafting and the send queue, so the UI never freezes. If the app is restarted, jobs pick up where they left off because their state lives in the database.

Instead of: Celery + Redis (extra services to install and run, overkill for one machine).

Claude Opus 5.5 AI model

Writes specific, human-sounding emails from lead data, extracts decision-makers from messy pages and plans target segments. Structured outputs guarantee clean JSON back, and automatic fallback covers rare refusals.

Effort is set to medium for writing and low for simple extraction, to keep costs down.

Claude web search & web fetch discovery

Finds real businesses for each segment and looks up decision-makers on LinkedIn and directories, without you buying a separate lead database or maps API.

Instead of: Google Places / Apollo / Hunter (paid per lookup, extra accounts). Needs web search enabled in the Claude Console.

requests + BeautifulSoup scraper

Fast, simple crawling of up to 6 key pages per site. It detects 55+ chat/AI tools, ad pixels, booking tools and CRMs, including those loaded through Google Tag Manager, and decodes Cloudflare-protected emails.

Playwright is optional, only for sites that need JavaScript to show content. It respects robots.txt and never guesses email addresses.

Rule-based score + AI writing hybrid

The AI Need Score comes from transparent rules (no chat, paid ads, no booking, English-only…), so it is consistent and free. Claude only does the parts rules can't: reading context and writing.

This also means scraping still works, with signals and score, if the AI is switched off.

Your own mailbox (SMTP / IMAP) email

Emails come from your real Hostinger address, so replies land in your normal inbox and it looks like personal outreach. IMAP lets the app spot replies, bounces and "unsubscribe" automatically.

Instead of: SendGrid/Mailgun (marketing-style sending, extra cost, worse for 1-to-1 cold email). Falls back between ports 465 and 587.

Queue with limits deliverability

A daily cap, random 90–240 s gaps, same-thread follow-ups, List-Unsubscribe headers and auto-stop on reply protect your domain's reputation and keep you within UK, Canadian and UAE outreach rules.

Excel in, Excel out openpyxl

Your workbook stays the shared format: import it, work in the app, export statuses back into the same file. Scraped leads export in the same column layout.

Local-first deployment

Runs on your laptop, so there's no server bill and your leads and keys stay on your machine. Deploy it (with a password) only if you want open tracking or access from anywhere.
